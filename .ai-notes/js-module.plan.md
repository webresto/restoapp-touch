## Срез 0 — доставка (сделано)

**Образец — сам модуль.** `simple-navigation` 1.7.1 (канал `staging`; в `main` 1.6.1 без админ-части):
модель `Navigation` — меню с `mnemonicId`, пункты списком в JSON-поле `navigation_menu`; админ-часть —
приложение adminizer `src/adminizer/NavigationApp.ts` (токен `navigation-manager`, четыре JSON-роута),
страница — `ui/NavigationManager.jsx`, собранная esbuild-ом в `assets/adminizer/NavigationManager.js`,
которую панель импортирует по URL от `ctx.asset()`; React и компоненты — глобали панели, в бандл не
входят. Мобильное повторяет это один в один.

**Сервер.** Регистрация с `script: {file}` — путь к собранному бандлу; хук читает и хеширует его один
раз (`lib/scripts.ts`), декларация несёт `script: {url, sha256, size, min}`, где url —
`/api/mobile/app-assets/<app>/<sha256>.js` (`http/routes/script.ts`, нужен токен устройства,
`immutable`). Хеш в имени: новая сборка — новая ссылка, чужой хеш — 404, кеш вечный; хеш входит в
ревизию декларации, поэтому после выкатки клиент сам перечитывает `describe`. Нет файла или пуст —
сервер не стартует.

**Модули в декларации.** `modules: [{id, version, kind: system|installed, title, app?, script?}]`:
`system` — из `MM_SYSTEM_MODULES`, `installed` — из менеджера модулей. У модуля, принёсшего
приложение, стоит `app` и та же ссылка — только если человеку это приложение доступно.

**Приложение.** «Навигация»: `apps/navigation.ts` + `adapters/navigation.ts`, методы
`navigation.menus / menu / create / save / remove`, право — токен самого модуля `navigation-manager`.
Бандл — из модуля (`assets/mobile/navigation.js`), а пока модуль его не везёт — из сборки хука
(`mobile-apps/navigation`, esbuild).

**Клиент.** `ScriptRef`, `ServerModule`, `MobileApi.script` (качает только со своего сервера, проверяет
размер и sha256; `sha256Hex` в commonMain), `ScriptLoader` + `ScriptCache` (кеш по хешу, откат на
последний удачный бандл, `min` выше протокола — не качаем). `ServerSession` качает сразу, как
декларация назвала скрипт, и держит файл в хранилище сервера (`script-<sha256>.js`).

**Чего в срезе 0 нет:** исполнять бандл нечем, поэтому в клиенте «Навигация» — плитка «Нужна новая
версия». Экран — срезы ниже.

## Как делать экран — два пути

| | A. Разметка с сервера (`ui.remote`) | B. Рантайм QuickJS (этапы 1–3 `script-apps.plan.md`) |
|---|---|---|
| Что приходит | дерево экрана данными на каждый запрос, строит модуль на сервере | один JS-файл, исполняется на устройстве |
| Что нужно в клиенте | рендер дерева из уже написанных компонентов `:render` + действия | модуль `superizer:script`: рантайм, маршруты, коллекции, кеш байткода (~3–4 тыс. строк) |
| Состояние экрана | у хоста (раскрытие, прокрутка) и на сервере | в JS, локально |
| Каждое нажатие | запрос | локально, запрос только за данными |
| Офлайн | нет | да (с `persist`) |
| Оценка | 1.5–2 недели | 4–5 недель |

**Решение владельца (Q1): B — рантайм QuickJS сразу.** Значит редактор навигации будет первым
приложением, которое по-настоящему исполняется на устройстве, а разметка с сервера (A) остаётся на
потом как третий источник того же рендера. Ниже — срезы под B; срезы под A сохранены в истории файла.

Что было рекомендовано и почему это не выбрано (для памяти): Редактору навигации
локальная логика не нужна: дерево ведёт хост, ввод — формы по JSON Schema, каждое нажатие и так идёт
на сервер. Набор компонентов, который делается для A, — это и есть `ui` v1 из плана скриптов, то есть
работа для B не пропадает. Доставка скрипта (срез 0) при A тоже не пропадает: модуль может прислать
**готовую разметку в скрипте** (источник 2 раздела 4 плана) — файл с деревом и действиями, без
исполнения; тот же бандл, тот же кеш по хешу.
