# RestoApp mobile admin — администрирование серверов, хост на Superizer

> Версия 0.2, 2026-11-02. Решения D1–D5, вопросы 1–3. Следующие номера — D6 / Q4.
> Статус: пустой хост (`composeApp/`), только десктоп, приложений нет; собирается, 2 теста. Перенесён из `../client/restoapp` в
> отдельный проект по просьбе владельца.

## Что просил владелец

«Новое приложение RestoApp, в нём будет всё, что нужно для администрирования сервера. Разные
приложения — как у Superizer, только можно задать глобальный контекст: мы подключаемся к разным
бекендам и получаем разное контекстное меню. Как это будет в UI — придумать позже; пока просто
пустое приложение». Затем: «перенеси в папку ../restoapp-mobile-admin».

## Решения

- **D1. Отдельный проект рядом с Unitool.** `/prj/restoapp-mobile-admin`, свой git и свой Gradle.
  Устроен как `../client`: `composeApp/` — только хост, приложения — модули `apps/<имя>`.
  Superizer — из исходников рядом (D4).
- **D2. Ничего общего с Unitool на одном устройстве.** `cx.m42.restoapp`, схема `restoapp://`,
  на десктопе настройки в `~/.restoapp` (`PrefsStorage.useDirectory`). Иначе два хоста делили бы
  Home, язык и снимок сессии.
- **D3. Пока пусто.** Ни одного приложения, без push, промокодов и иконки. Язык по умолчанию —
  русский.
- **D4. Superizer — из исходников, обязательно.** Владелец: «исходник superizer, чтобы через него
  делать всё». `../superizer` (git-клон `adminization/superizer`) подключается `includeBuild`;
  без него сборка останавливается с подсказкой, как его склонировать. Глобальный контекст и всё,
  что понадобится хосту от библиотеки, правится прямо там. `SUPERIZER_FROM_MAVEN=1` — сборка из
  mavenLocal, как у Unitool в CI.
  - В корне проекта — симлинк `superizer -> ../superizer` (как `unitool-app-example -> ../client`):
    исходники библиотеки видны и правятся из дерева этого проекта. Сборка смотрит на `../superizer`
    напрямую; ссылка — только для удобства, это тот же клон, что у Unitool.
- **D5. Только десктоп.** Владелец: «останавливай андроид, будем делать только десктоп». Модуль
  остаётся мультиплатформенным (`jvm("desktop")`), Android, веб и iOS возвращаются как таргеты, а не
  переписыванием. Android и веб убраны вместе с исходниками (были пустыми: `MainActivity`,
  манифест, `main` для wasm).
  - Почему остановили: на этой машине (i7-4770HQ, macOS 12.7) сборка Android четыре раза подряд
    вставала на `mergeExtDexDebug` — Gradle-демон зависал целиком: один поток крутится в Java-коде,
    VM Thread ждёт его в `VM_HandshakeAllThreads`, GC и `jcmd` не проходят. Так на Temurin 21.0.13,
    21.0.8 и с `-XX:TieredStopAtLevel=1`, то есть не баг C2. Десктоп на тех же JDK собирается.
    Прежде чем возвращать Android — разобраться (другой JDK — 17, `--no-daemon`,
    `org.gradle.workers.max=1`) или собирать на другой машине/в CI.

## Если окно не реагирует на мышь (2026-11-02)

На этой машине окно рисовалось, но ни кнопки, ни меню не нажимались. Причина — не приложение:
macOS считала **правую и среднюю кнопки мыши зажатыми** (`NSEvent.pressedMouseButtons = 6`), Java
передавала это в каждом событии (`extModifiers=Button2+Button3`), и Compose не засчитывал клик —
указатель для него так и не отпускался. Лечится нажатием и отпусканием правой и средней кнопок
(или переподключением мыши). Нажатия через Accessibility при этом работают — по этому и видно.
Тест `clickingTheBurgerWithAMouseOpensTheDrawer` держит, что сам хост мышь понимает.

## Открытые вопросы

- **Q1. Что такое «глобальный контекст».** Бекенд = адрес + учётные данные? Сервер по SSH?
  Несколько сразу или один активный? Переживает ли перезапуск, где хранится секрет доступа (vault)?
- **Q2. Как контекст меняет набор приложений и меню.** Варианты: (а) приложение объявляет, с
  каким типом бекенда работает, и хост показывает только подходящие; (б) бекенд сам отдаёт список
  разделов/меню, и хост строит его; (в) смесь. И где это живёт: в хосте поверх
  `register`/`home`, или в Superizer как общий механизм (`runtime.context`, фильтр в реестре).
- **Q3. Общий код с Unitool.** Сервисы из `../client/services` (ssh, vault, qr-scanner) отсюда
  напрямую не видны. Когда понадобятся: перенести в Superizer, публиковать из client или
  подключать `includeBuild("../client")`. И UI переключения контекста — шапка, drawer, экран
  выбора при старте — позже, вместе с первым настоящим приложением.
