# Прототип: Preact в QuickJS → Compose

> 2026-11-03. Проверка идеи из `../qucik.md` («свой React Native»: JSX → Preact → QuickJS → мутации →
> Kotlin → Compose). Не часть приложения: отдельная сборка, в Gradle проекта не входит.

## Запуск

Из корня проекта:

```sh
JAVA_HOME=~/Library/Java/JavaVirtualMachines/jdk-17.0.21+9/Contents/Home \
  ./gradlew -p .ai-notes/quick/kt desktopTest
```

Первый запуск сам делает `npm ci` в `js/` и собирает `js/dist/bundle.js` (esbuild). Нужен Node
(проверено на 24.21). JDK — 17: на 21 эта машина виснет (D5 в `../README.md`).

## Устройство

- `js/src/app.tsx` — то, что прислал бы сервер: экраны `counter` и `orders` на Preact и хуках.
  Компоненты хоста — просто строки (`"Column"`, `"Text"`, `"Button"`), Preact считает их DOM-тегами.
- `js/src/host.ts` — поддельный DOM. Preact рендерит в него, каждая операция становится мутацией
  (`create` / `text` / `set` / `listen` / `insert` / `remove`), пакет уходит в Kotlin **одним** вызовом
  `__host.commit` после рендера. Таймеры (`setTimeout`) и вызовы сервисов (`call(service, method, args)` →
  Promise) ведёт Kotlin. Входы из Kotlin: `__mount`, `__dispatch`, `__fireTimer`, `__rpcSettle`.
- `kt/.../JsRuntime.kt` — QuickJS (quickjs-kt 1.0.15) на своём потоке; все входы в JS — по одному.
  Лимиты: память 32 МБ, стек 512 КБ, 250 мс на вызов.
- `kt/.../UiTree.kt` — дерево узлов хоста; пакет применяется внутри mutable snapshot Compose.
- `kt/.../Render.kt` — Compose только читает дерево (`Column`, `Row`, `Text`, `Button`); QuickJS
  composable-функции не вызывает.
- `kt/.../SpikeTest.kt` — четыре теста, результаты ниже.

## Результаты (этот Mac: i7-4770HQ, macOS 12.7, JDK 17)

| Что проверено | Результат |
|---|---|
| Нажатие в Compose → `useState` в JS → Compose | работает; на нажатие — одна мутация, только изменившийся текст |
| `useEffect` + вызов сервиса (Promise ↔ suspend) | список заказов приходит |
| `setTimeout` через таймеры Kotlin | работает |
| Перестановка по `key` | 2 мутации, узлы переставлены, а не пересозданы |
| Бесконечный цикл в обработчике | прерван через ~250 мс, рантайм работает дальше |
| Без Preact: JS каждый раз отдаёт весь экран данными, сравнивает Compose | список из 500 строк — 59 КБ JSON, ~6 мс на обновление (построить, сериализовать, разобрать в Kotlin) |
| Скорость | 0,5–1 мс на полный круг нажатия; запуск и монтирование 7–25 мс (первый — 0,3–0,45 с, загрузка нативной библиотеки); куча JS 200–270 КБ; бандл 17 КБ (7 КБ gzip) |

Подвох, пойманный по дороге: Preact пишет `dom[prop] = value`, если у узла есть такое поле, — проп
`id` или `data` молча портил узел. Внутренние поля узла названы так, чтобы не совпадать с пропсами.

## Что не проверено

- Android и iOS (quickjs-kt их поддерживает; Android на этой машине не собирается — D5).
- Ввод текста, длинные списки с виртуализацией, навигация.
- Откат пакета при ошибке протокола: заложен через snapshot, теста нет.
- Source maps: ошибки приходят как `main.js:1:17375`.
- Загрузка, подпись и обновление бандла на лету.

## Поправки к `../qucik.md` (сверено с первоисточниками 2026-11-03)

- **Сторы — риск преувеличен.** Google Play: запрет на загрузку кода «does not apply to code that runs
  in a virtual machine or an interpreter… (such as JavaScript…)». Apple, лицензионное соглашение
  §3.3.1(B): скачиваемый интерпретируемый код разрешён, если не меняет назначение приложения, не
  обходит защиту ОС и не делает магазин приложений (на этом работает Expo EAS Update). Отдельный
  «store-safe режим» не обязателен.
- **Zipline для JSX не подходит:** обычный JS выполняет, но вызывать хост из него может только
  Kotlin/JS (`ZiplineService`). Реальный выбор — quickjs-kt.
- **Не упомянут ближайший аналог** — tiny-ui/tinyui (сентябрь 2026): TSX → QuickJS → Compose
  Multiplatform, но со своим runtime на сигналах вместо Preact.
- Redwood свёрнут (последний релиз 0.19.0, ноябрь 2025), но не архивирован; Keliver уже 0.4.1.
